## 요약

**작업 디렉토리 및 프로젝트 구조**
사용자의 작업 디렉토리는 `~/tmp`이며, 그 안에 `fear-greed-data/` 프로젝트가 있다. 이후 사용자가 `raddit` 폴더를 언급하여 `/home/user/raddit`로 이동했다. `raddit`은 Reddit 주식 언급량을 집계하고 $5 미만 페니주식을 필터링하는 대시보드 프로젝트로, `raddit-reddit/`(Python FastAPI Reddit RSS 수집 RPC 서비스), `raddit-astro/`(Astro 웹 대시보드 메인), `raddit-next/`(Next.js), `docs/`(경쟁사 리서치 문서)로 구성되어 있다. CONTRIBUTING 규칙은 main/dev 직접 push 금지, 이슈→토픽 브랜치→PR, FF 머지 금지를 명시한다.

**브랜치 동기화 및 분석**
`git pull`로 dev와 main을 origin 최신화했다. dev는 이미 최신(0/0)이었고, main은 25커밋 뒤처져 fast-forward로 동기화했다(ca7ca30). 현재 작업 브랜치는 `feat/lightweight-charts`로, origin/dev(65d88b6)와 동일하며 미커밋 변경사항으로 `raddit-astro/package*.json`에 lightweight-charts 의존성만 추가된 상태였다. main이 dev보다 5개 merge 커밋 앞서 있었지만, `git diff origin/dev origin/main` 결과가 비어 있어 내용은 100% 동일했다. 이는 CONTRIBUTING의 "FF 머지 금지, 무조건 머지커밋" 규칙 때문으로 정상 동작이었다.

**차트 스케일 찌그러짐 버그 (PR #50)**
이슈 #49로 등록된 "봉 간격 전환 시 가격 스케일이 갱신 안 되어 차트가 위아래로 찌그러짐" 문제를 분석했다. 결정적 재현으로 원인을 특정했다: 오버레이(MA/BB)는 day(일봉)에서만 제공되는데, lightweight-charts가 같은 가격 스케일의 모든 시리즈 합집합으로 Y축을 자동 산정하여 넓은 BB 밴드(±2σ)가 Y축을 확장해 캔들을 찌그러뜨렸다. 구 Canvas 차트는 캔들 데이터만으로 Y축을 정하고 오버레이를 clip했기에 없었던 문제(PR #47 이관 회귀). 재현 결과: min→day 전환 시 캔들 실제 범위가 차트 높이의 ~35%로 압축(priceToCoordinate 픽셀 측정, 2회 확인). 수정(3줄): 오버레이 시리즈에 `autoscaleInfoProvider: () => null` 추가 → 자동 스케일 산정에서 제외, 캔들 데이터만으로 Y축 결정. PR #50 → dev 머지(머지커밋 0e62967), 이슈 #49 종결.

**가격 스케일 수동 조작 후 찌그러짐 (PR #52)**
사용자가 가격(Y) 스케일을 수동 줌/드래그하면 lightweight-charts가 `autoScale`을 끄고 수동 범위로 고정하는 것이 원인이었다. 이후 `setData`+`fitContent`(시간축만)해도 가격 스케일이 자동 리핏 안 되어 이전 수동 범위가 잔존했다. PR #50(오버레이)과 별개 원인으로, 둘 다 필요했다. 수정(6줄): `drawChart`에서 레인지 변경 시 `candleSeries.priceScale().applyOptions({ autoScale: true })` 재활성화. 단, 동일 레인지 60초 자동갱신에선 사용자 줌 존중(`lastRange`로 구분). 결정적 재현/검증: 수정 전 min 캔들 3%(8px) 찌그러짐 → 수정 후 63%(175px) 정상. PR #52 → dev 머지(머지커밋 f4304e7).

**ApeWisdom 페니주식 필터 개선 (PR #51)**
현재 ApeWisdom은 751개 전체 티커를 가져오면서 상위 120개만 가격조회하고 나머지를 버려(16%만 활용), $5 미만 페니주식 89개 중 62개(70%)가 랭크 401번 이후 깊은 곳에 묻혀 `slice(0,120)`에서 잘려나갔다. 게다가 `FALSE_POSITIVE`(EU·IQ·RR·DC·LINK)가 실제 <$5 주식까지 덮어 제거했다. 핵심 수치: 현재 회수율 29%(14개 중 4개만 노출). 수정:
1. `attachQuotesBatch` — Yahoo spark 배치(20심볼/요청, 비인증) 전수 가격조회, per-ticker v8/chart 제거 → 요청 ~20배 절감
2. `getData` — `slice(120)` 제거 → 전수조회 후 가격 필터, 페니모드는 EQUITY만(ETF 제외)
3. `FALSE_POSITIVE` — 실제 <$5 주식은 보존(EU·IQ·RR·DC·LINK 회수)

architect 리뷰 후 추가 수정:
- P1: Yahoo 429 대량 실패 시 누락률 70% 초과 시 throw → 직전 정상 스냅샷 서빙(stale-if-error 보호)
- P2: 순차 38청크 → 동시성 5 병렬로 콜드 로딩 11s+ → 2.5s
- P3: FP 보존 임계값 가격필터 연동

실측(/api/data?max_price=5): 노출 4건 → 19건(회수율 ~100%), EU/IQ/RR/DC/LINK 회수, ETF 노이즈 제거. PR #51 → dev 머지(머지커밋 57c5337).
